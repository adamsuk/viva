# Changelog

All notable changes to Viva are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Viva is a live site with no version numbers, so each section is the date the change merged (YYYY-MM-DD, Europe/London).

Research-driven entries say what changed, why, and which sources back it. See [CONTRIBUTING.md](CONTRIBUTING.md).

## 2026-11-23

### Added

- Factory onboarding. `.github/factory.yml` (builder and reviewer roles, agents never merge, test command `npm run typecheck && npm run lint && npm test`, required checks `test` and `changelog`), `AGENTS.md` with the build, content, log-schema and privacy rules, `CODEOWNERS`, a task issue template and a size-label caller pinned by SHA. Why: so the software factory can triage, build and review changes here under its shared rules ([adamsuk/software-factory#455](https://github.com/adamsuk/software-factory/issues/455), [#2](https://github.com/adamsuk/viva/pull/2)).

### Changed

- The personal map keeps your log in this browser. New pastes and files add to what is kept, with identical lines kept once, or replace it if you choose. Download log saves a copy and Forget this log deletes it. The page says what is kept, where and until when, and still works for the visit when the browser blocks storage. The sample is shown but never kept. Why: both viva skills tell users without a filesystem that the map stores the log in the browser, but it forgot everything on reload, so no picture could build up over time. The research says to say what is collected and for how long before collecting it ([adamsuk/software-factory#458](https://github.com/adamsuk/software-factory/issues/458), [#3](https://github.com/adamsuk/viva/pull/3)).
- Log schemas say which skill versions write them (`skillVersions`, for example `0.3.x`), and the parser picks a schema by exact version, then by that range. Lines from the current `viva` skill (0.3.3) now match the 0.3 schema instead of falling back. The map says how many lines it skipped or read with an unknown version, and groups topics ignoring case and extra spaces. Why: the skill writes 0.3.3 but the platform only knew 0.3.1, and malformed lines vanished without a word, so a user could not tell why checks were missing ([adamsuk/software-factory#459](https://github.com/adamsuk/software-factory/issues/459), [#4](https://github.com/adamsuk/viva/pull/4)).

## 2026-11-21

### Changed

- Personal map imports keep the latest selection, show a retry message when a file cannot be read, and link to the published MVP notes. Negated grades such as `not understood` now surface confident misses.

## 2026-10-30

### Added

- Evidence labels on the setup options and the factory notes, from targeted research. Each one now carries a strength label and says what it rests on. Most are Gap or Opinion: nobody has tested a follow-up check against none, a walkthrough as a check, or understanding inside an agent factory. Adds 15 claims under Software factories and Alternatives, three open questions and two experiments. Why: the setup options and factory mode were design reasoning shown without labels, and several factory notes cited Line itself as evidence, which is circular. Line is no longer cited as a source. Sources: [How Humans Review AI-Generated Pull Requests](https://arxiv.org/abs/2605.02273) (EASE 2026), [More Code, Less Reuse](https://arxiv.org/abs/2601.21276) (MSR 2026), [Does Working with AI Agents Change How Developers Code, Test, and Review?](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ESEM.2026.67) (ESEM 2026), [AgentStepper](https://arxiv.org/abs/2602.06593) (6 February 2026), [Rigby and Bird](https://www.microsoft.com/en-us/research/publication/convergent-software-peer-review-practices/) (2013), [Ram and others](https://zenodo.org/records/1323659) (2018), [Myers](https://doi.org/10.1145/359588.359602) (1978), [Palmer, Holt and Bray](https://ascilite.org/conferences/melbourne08/procs/palmer.pdf) (2008), [Plonka and others](https://doi.org/10.1016/j.ijhcs.2014.09.001) (2015), [Hannay and others](https://doi.org/10.1016/j.infsof.2009.02.001) (2009), [Avelino and others](https://doi.org/10.1109/ICPC.2016.7503718) (2016), [Rigby and others](https://doi.org/10.1145/2884781.2884851) (2016).
- Set up the walk: who builds the change (people with AI, or a software factory as in Line), the follow-up check (a viva question, a walkthrough, or none), and what is kept (a private map, a learning log, or none). With none, a station is marked N/A and skipped. The team audit offers N/A on the questions about these ideas and leaves it out of the score. Why: the follow-up check and the map are Viva's own untested product idea, and the rest of the guide should stand without them.
- Factory mode. Every station has a note on what changes when agents build from work orders. Draft becomes writing the checks and reading the agent's session, and a vague work order is sent back. Post requires an evidence record instead of the agent's claim of done. The follow-up check goes to the approver and the work order owner, and is never a required gate check. Return can route a thin area to a person. A new guide section and README tables compare the two. Why: to show how the walk fits a factory as Line defines it. Sources: [Line](https://adamsuk.github.io/line/), [Code Review After Code Gets Cheap](https://www.oreilly.com/radar/code-review-after-code-gets-cheap/) (16 October 2026), [Who Holds the Pen?](https://arxiv.org/abs/2609.29921) (24 September 2026), [AI Writes Faster Than Humans Can Review](https://arxiv.org/abs/2607.01904) (2 July 2026).
- The first research notes: claims labelled by strength, prior art, open questions, and an experiment log.
- A walkable site in the style of [Line](https://github.com/adamsuk/line): one AI-assisted pull request, #212, moves through eight stations (Draft, Post, Bot review, Review, Viva, Merge, Map, Return). Weak choices are sent back: an agent-written description, a forwarded bot comment nobody checked, a rubber-stamp approval, a hard block on a quiz, and a ranked dashboard of people. Why: the notes argued for checks on understanding but did not show where they fit in a real review.
- The guide: three adoption stages, a table of where people stay in the loop, 23 recommendations labelled Best practice or Cutting edge, the evidence as 29 claims labelled by strength, prior art with the gap each tool leaves, open questions and experiments, and Audit your team. Answers stay in this browser.
- guide.json, llms.txt and llms-full.txt, built from the page's data and versioned by this changelog, with a read-only audit prompt that is told not to look at individuals.
- New research behind the stations. Sources: [(Im)Paired Programming](https://arxiv.org/abs/2607.26375) (29 July 2026), [Students Struggle to Explain Their Own Program Code](https://arxiv.org/abs/2104.06710) (2021), [Let's Ask AI About Their Programs](https://arxiv.org/abs/2404.11734) (2024), [LLVM AI Tool Use Policy](https://llvm.org/docs/AIToolPolicy.html), [Linux kernel AI Coding Assistants](https://docs.kernel.org/process/coding-assistants.html), [Bacchelli and Bird](https://web.eecs.umich.edu/~weimerw/2018-481/readings/codereview.pdf) (2013), [Perry and others](https://arxiv.org/abs/2211.03622) (2023), [Ravid and others on monitoring](https://doi.org/10.1111/peps.12514) (2023), [the EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj), [Adesope and others](https://doi.org/10.3102/0034654316689306) (2017), [Bisra and others](https://doi.org/10.1007/s10648-018-9434-x) (2018), [Feng and others](https://arxiv.org/abs/2602.00496) (CHI 2026), [METR's 2026 update](https://metr.org/blog/2026-02-24-uplift-update/), and the [Canaries in the Coal Mine](https://digitaleconomy.stanford.edu/app/uploads/2025/11/CanariesintheCoalMine_Nov25.pdf) revision.
- Two new tools in prior art: [Sphinx](https://github.com/parthh01/sphinx), a push hook, and [PR Quiz Gate](https://github.com/michaelbeutler/pr-quiz), which quizzes reviewers. Neither has published evidence.
- A pull-request check that runs typecheck, lint and tests, a Pages deploy, and a changelog check.

### Changed

- A visual identity of its own, so Viva no longer reads as a copy of Line. It is styled as an exam booklet: ruled ivory paper, a red margin rule, and blue examiner's ink as the accent, set in Newsreader and Schibsted Grotesk. The header is a masthead with underline tabs and eight tick boxes for progress. Stations are a numbered question index, each lesson is an "Examiner's note", and labels are outlined stamps. Corners are flat and there is a dark mode. Why: Scott asked for a style that is not a carbon copy of Line.
- The confidence-weighted testing claim now cites its authors, Sparck, Bjork and Bjork (2016). It was attributed to "Little et al.", whose earlier work it builds on. Source: [On the learning benefits of confidence-weighted testing](https://doi.org/10.1186/s41235-016-0003-x).
- The review-agent claim now says what the paper measured: 12 of 13 agents had an average signal ratio below 60%, and agent-only PRs merged at 45% against 68% for human-only review. It said "actionable comments" and "human comments were addressed far more often", which the paper does not report. Source: [arXiv 2604.03196](https://arxiv.org/abs/2604.03196).
- The METR follow-up claim now quotes METR's own post: it could not measure the effect reliably and calls its evidence very weak. Secondary write-ups had cited an 18% speedup that METR did not report. Source: [We are Changing our Developer Productivity Experiment Design](https://metr.org/blog/2026-02-24-uplift-update/).
- The GPT-4 figure (88% of questions about code) is now checked against the paper: 399 questions, 88% for GPT-4 and 69% for GPT-3.5.
- The junior employment claim now links the Stanford paper and its February 2026 note instead of a news summary, and adds that under stricter controls the drop is significant only after 2024.
- Secondary sources that the primary research replaced were removed: Codacy, Faros, Structify, ai2.work and two news summaries.
